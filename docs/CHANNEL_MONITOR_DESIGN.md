# Дизайн: шаблон `channel_monitor`

## 1. Техническое ограничение (проверено на практике в этом стеке)

Вся фабрика построена на **aiogram + Bot API** (см. [main.py](../main.py), [templates/moderator.py](../templates/moderator.py)).
Bot API не даёт боту читать историю сообщений произвольного публичного канала "по ссылке" —
он получает только **обновления (updates)** для чатов, где сам является участником/админом:

- `my_chat_member` — приходит боту, когда его добавляют/убирают/меняют права в чате или канале.
  Уже используется в `moderator.py` (`on_bot_membership_changed`, [templates/moderator.py:468](../templates/moderator.py#L468))
  как единственная точка, где бот узнаёт о своём статусе в группе — тот же механизм работает и для каналов.
- `channel_post` (и `edited_channel_post`) — приходит боту только по **новым** постам в канале,
  где бот сейчас является администратором. Это единственный способ Bot API "видеть" контент канала.
  Ни исторические посты (до добавления бота), ни посты чужого канала без прав администратора
  боту недоступны.
- `main.py` работает на polling с явным `allowed_updates=[...]` ([main.py:220](../main.py#L220)) —
  сейчас туда включены `message`, `callback_query`, `inline_query`, `my_chat_member`, `managed_bot`.
  Для управляемых ботов (`build_group_router()`, [main.py:49](../main.py#L49)) действует тот же принцип.

**Вывод:** "мониторинг любого чужого публичного канала по ссылке" в чистом Bot API/aiogram нереализуем.
Два теоретических обхода:
1. Бот должен быть добавлен администратором **в каждый** отслеживаемый канал — зависит от владельца
   ЧУЖОГО канала, не только владельца нашего бота.
2. Telegram Client API (Telethon/Pyrogram) — требует авторизации живого пользовательского аккаунта,
   не бота: другая архитектура, риск бана аккаунта, вне текущего стека aiogram. **Отклонено** —
   не совместимо с остальной фабрикой ботов.

## 2. Принятый вариант (в рамках текущей архитектуры)

`channel_monitor` отслеживает **только те каналы, куда владелец сам добавил этого бота администратором**
(своя сеть каналов + партнёрские, куда его пустили). Это НЕ "любой чужой канал по ссылке" — это
"каналы, куда бота пустили". Ограничение объясняется явно:

- В дизайн-документе (этот файл) — see выше.
- В самом боте — при попытке "добавить канал" до того, как бот реально видит его как админа,
  показывается понятный текст-инструкция, а не молчаливый провал (см. §4).

## 3. Схема БД

```sql
CREATE TABLE monitored_channels (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    channel_id INTEGER NOT NULL,
    channel_title TEXT,
    active INTEGER DEFAULT 1,
    added_at TEXT DEFAULT (datetime('now','localtime'))
);

CREATE TABLE channel_posts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    channel_id INTEGER NOT NULL,
    message_id INTEGER,
    text TEXT,
    posted_at TEXT DEFAULT (datetime('now','localtime'))
);
```

`channel_id` в обеих таблицах — Telegram chat_id канала (отрицательное число вида `-100...`).
Уникальность `monitored_channels.channel_id` обеспечивается на уровне upsert-логики (как
`known_groups` в moderator.py), а не UNIQUE-constraint — так проще делать "мягкое" переоткрытие
(канал убрали и снова добавили).

## 4. Поток владельца

### «➕ Добавить канал»
Т.к. бот не может "подключиться" к каналу по ссылке — только узнать о своём членстве через
`my_chat_member` — поток такой:
1. Владельцу показывается инструкция: добавить ЭТОГО бота администратором в канал (право
   "публикация сообщений" не нужно — достаточно любого админского доступа, чтобы Telegram
   стал слать `channel_post`).
2. Владелец жмёт «Готово, я добавил» → бот вызывает `bot.get_chat_member(channel_id, bot.id)` по
   введённому username/id канала (или полагается на `my_chat_member`, который уже мог прийти
   раньше — идемпотентно).
3. Если бот реально видит канал как участник/админ — `monitored_channels` upsert, канал появляется
   в списке.
4. Если нет — понятное сообщение: «Не вижу этот канал. Добавьте бота @<username> администратором
   канала и повторите — без этого шага мониторинг технически невозможен (ограничение Telegram Bot API,
   не наша фабрика)».

Основная точка появления канала — тот же паттерн, что в moderator.py: `my_chat_member` handler
сам апсертит канал при получении события "добавлен как админ", без участия пользователя в диалоге
(канал появляется в списке даже если владелец не нажал «Готово» — событие приходит раньше).

### «📋 Мои каналы»
Список `monitored_channels` (активные и скрытые), кнопка toggle `active` на каждой строке.

### «📰 Лента»
Последние `channel_posts` из каналов с `active=1`, отсортированные по `posted_at DESC`, с пагинацией.

## 5. Сбор постов
`channel_post` handler (аналог `on_bot_membership_changed` по структуре) пишет новый пост в
`channel_posts`, только если `channel_id` состоит в `monitored_channels` (не обязательно active —
скрытые каналы тоже продолжают копиться, чтобы включение не теряло историю с момента добавления).

## 6. Стоп

Дизайн-документ описывает урезанный, но технически реальный вариант: **мониторинг только каналов,
куда бота добавили администратором**, не произвольных чужих каналов по ссылке. Жду подтверждения
перед реализацией.
