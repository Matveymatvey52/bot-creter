# Мини-приложения: капитальный редизайн + отдельный веб-сайт вне Telegram

Статус: **дизайн, ждёт подтверждения владельца**. Кода не писать, пока не подтверждено.

## 0. Инвентаризация текущего состояния

- 32 шаблона в `templates/*.py` — у каждого `miniapp_config` (декларативная схема resources/fields), нет отдельного UI-кода на шаблон.
- Все они рендерятся через 3 общих экрана: `ListScreen.tsx`, `DetailScreen.tsx`, `CreateFormScreen.tsx` + примитивы `components/Card.tsx` (Card/CardHeader/CardTitle/ChipRow/Chip/Badge) + `components/ui.css`.
- Стили — обычный CSS (не Tailwind), токены палитры уже в `index.css` (`--bg`, `--surface`, `--accent: #7c5cff` и т.д.) — тёмная фиолетовая палитра, которая владельца уже устраивает.
- Авторизация Telegram: `lib/telegram.ts` → `X-Telegram-Init-Data` header → `runtime/miniapp_api.py:_authenticate()`.
- Magic-link токен уже существует и используется — не для клиентских ботов, а для owner-only factory dashboard (`/app/0`): `mint_magic_link_token()`, TTL 15 мин, `?token=` query param, автопродление через `POST /api/factory/session` (`lib/factoryApi.ts`). Ровно тот механизм, который нужен для клиентского веб-сайта вне Telegram.
- 5 самописных экранов (FactoryDashboard, OwnerRegistry, OwnerReport, BotDetailPanel, Analytics) не проходят через общие Card/CSS-токены единообразно — это отдельный объём работы, если их тоже нужно перекрасить.

Вывод: редизайн общих компонентов автоматически покроет все 32 шаблона — правка ~4 файлов (`Card.tsx`, `ui.css`, `index.css`, 3 generic screens). Bespoke-экраны — отдельная, некаскадная работа.

## 2. Задача Б: отдельный веб-сайт для каждого клиентского бота (вне Telegram)

Отличается от задачи А масштабом — это новая инфраструктура авторизации и роутинга, не просто UI.

### 2.1 Авторизация

Переиспользуем существующий magic-link механизм (`mint_magic_link_token`/`_verify_magic_link_token`), уже проверенный на factory dashboard:

- Клиент открывает бота → команда/кнопка "🌐 Открыть на сайте" → бот минтит token с TTL (предлагаю 24 часа вместо 15 мин — это не Telegram WebView-сессия, а "открыл с ноутбука и работаю какое-то время") → присылает ссылку вида `https://<host>/site/{bot_id}?token=...`.
- Бэкенд: `_authenticate()` в `miniapp_api.py` уже умеет token-путь как fallback — расширить, чтобы этот путь стал основным (не только fallback) для `/site/*` роутов, без обязательного `X-Telegram-Init-Data`.
- Автопродление сессии по образцу `factoryApi.ts` (`POST /api/factory/session` → новый общий `POST /api/bot-session`).

### 2.2 Роутинг/фронтенд

- Новый top-level route в `App.tsx`: `/site/{bot_id}` — рендерит те же generic screens (List/Detail/CreateForm), что и Telegram Mini App, без обёртки Telegram WebApp SDK (`lib/telegram.ts` вызовы должны деградировать до no-op вне Telegram — проверить также `useMainButton.ts`, который использует Telegram MainButton API и должен подменяться обычной кнопкой на сайте).
- UI-слой общий с задачей А — сайт получает новый дизайн бесплатно, если он сделан компонентно.

### 2.3 Деплой/URL

- Один и тот же Vite build, тот же `runtime/miniapp_api.py` backend — просто новый маршрут, не отдельный сервис. Не нужен отдельный Railway-сервис на бота.
- URL формата `https://<domain>/site/{bot_id}` — уточнить у владельца, нужен ли красивый поддомен на бота (`{bot_slug}.domain.com`) или устраивает путь.

### 2.4 Объём

Требует: доработку `_authenticate()` (auth-путь без Telegram), новый route + условный рендеринг без Telegram SDK, продление токена на сайте, кнопку "открыть на сайте" в боте. Больше, чем задача А — новая ветка авторизации и её тестирование (истечение токена, повторная выдача, поведение без Telegram-контекста). По объёму сопоставимо с прошлым multitenancy-этапом (auth + routing), не биг-банг, но требует отдельного захода.

## 3. Порядок и зависимости

Задача А не зависит от Б и может катиться первой — она улучшает и Telegram Mini App, и будущий сайт одновременно (сайт наследует новые компоненты).
Задача Б технически может стартовать на старом UI и получить редизайн следом, но логичнее делать А → Б, чтобы не переверстывать экраны дважды.
