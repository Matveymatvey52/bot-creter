# Bot mini-app SPA

Generic Telegram Mini App front-end for bots created by this project. It talks to
`runtime/miniapp_api.py`'s REST layer (`GET/POST /api/{bot_id}/{resource}`) and renders
list / detail / create screens for whatever resources a bot's template declares.

The SPA itself has no per-bot logic in it. All bot-specific content — which resources
exist, what their fields are called, how they're labeled and formatted — lives entirely
in the bot's own `miniapp_config` (hand-authored in a template module, e.g.
`templates/tour_operator.py`, or generated by the Haiku step in
`services/claude_service.py` for arbitrary bots). The SPA fetches this once per session
from `GET /api/{bot_id}/schema` and normalizes it client-side in
[`src/lib/displaySchema.ts`](src/lib/displaySchema.ts) — there is no static per-bot file
to hand-edit anymore (that used to be `src/lib/resources.ts`, since removed).

## Adding a new bot

1. Make sure the bot's template module (e.g. `templates/car_rental.py`) exports a
   `miniapp_config` dict describing its resources AND their display metadata, matching
   the shape already used by `templates/tour_operator.py`:

   ```python
   miniapp_config = {
       "resources": [
           {
               "name": "cars",
               "table": "cars",
               "order_by": "created_at DESC",
               "creatable": True,
               "title": "Машины",        # tab label / list-screen heading
               "titleField": "make",     # which field is shown as the item's heading
               "fields": [
                   {
                       "name": "make", "required": True,
                       "label": "Марка", "kind": "text",
                       "list": False, "detail": False, "create": True,
                   },
                   {
                       "name": "status",
                       "label": "Статус", "kind": "status",
                       "list": True, "detail": True, "create": False,
                   },
                   {
                       "name": "created_at", "creatable": False,
                       "label": "Создано", "kind": "date",
                       "list": False, "detail": False, "create": False,
                   },
               ],
           },
           ...
       ],
   }
   ```

   This is the ONLY per-bot file the SPA needs — both the server-side data contract
   (which columns exist, which are writable/required — read by `miniapp_api.py`'s
   generic CRUD handlers) and the client-side display contract (labels, widget `kind`,
   which screen shows which field) live in the same dict. `kind` is one of
   `'text' | 'number' | 'date' | 'status'`. `list`/`detail`/`create` are independent
   per-field booleans controlling which of the three screens shows that field (order in
   the `fields` array is the display order within each screen); a field can be
   `creatable: True` at the DB layer yet `create: False` on the form (e.g. a
   foreign-key id nobody should type by hand).

   For arbitrary bots generated at bot-creation time, `services/claude_service.py`'s
   `_generate_miniapp_config()` produces this same shape automatically (one cheap Haiku
   call reading the bot's own `init_db()` CREATE TABLE statements) — nothing to hand-
   author for those. All display keys are optional: an older/pre-migration config
   missing them still renders, via `displaySchema.ts`'s fallback defaults (humanized
   field name as label, "text" kind, empty list-chips, everything creatable).

2. That's it — no frontend file to touch. `App.tsx` fetches `GET /api/{bot_id}/schema`
   once on load and passes the resulting `ResourceDisplay` objects down to
   `ListScreen`/`DetailScreen`/`CreateFormScreen` as props; none of them import a
   per-bot file. The whole `miniapp/` directory is one build shared by every bot.

## What NOT to hardcode elsewhere

If you find yourself adding a resource or field name to any SPA source file, that's a
sign the change belongs in the bot's `miniapp_config` instead — it keeps the SPA
reusable across templates without code changes.

## Development

```sh
npm install
npm run dev       # dev server; see vite.config.ts for the API proxy
npm run build      # outputs to dist/, served by combined_app.py at /app/{bot_id}
```
